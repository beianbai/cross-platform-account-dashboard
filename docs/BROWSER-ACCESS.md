# 独立版多浏览器访问授权

状态：0.7.0 实现；范围为独立服务，不修改 DSH 宿主登录与采集连接机制。

## 用户流程

固定地址始终提供入口。未授权浏览器看到配对页；已授权浏览器直接进入看板。首次配对码在启动终端取得，后续可从另一终端或已授权浏览器的设置生成，无须停止服务。地址不含凭据，点击聊天链接不会提前用掉配对码。

一次配对只授予当前浏览器配置文件访问权限。多个浏览器共享服务端业务数据，拥有相同的工作台操作与授权管理权限。浏览器名称来自 User-Agent，仅用于辨认，不是设备身份证明。不同浏览器的主题等本地偏好独立保存。

## 状态与持久化

| 对象 | 生命周期 | 保存位置 |
| --- | --- | --- |
| 配对码 | 8 位随机字符，5 分钟，成功使用一次；重新生成或停服即失效 | 服务内存仅保存哈希；明文只在签发响应或终端短暂展示 |
| 浏览器会话 | 每个浏览器独立随机令牌；90 天未访问失效，可单独撤销 | Cookie 保存令牌；`standalone-session.json` v2 保存哈希、标识、名称、授权和访问时间 |
| 终端管理凭据 | 每次服务启动轮换，正常停止时清除 | `.standalone-control.json`，仅限本机文件访问 |
| 业务数据 | 与授权生命周期无关 | 原有业务文件；访问授权升级和恢复不修改业务文件 |

授权文件以 0600 临时文件写入、同步后原子替换。每分钟最多持久化一次访问时间；异常退出时，最后访问时间可能落后一小段时间。配对、签发与撤销通过串行队列处理；只有会话写入成功才消耗配对码，两个并发兑换最多一个成功。最多保留 100 个有效会话；过期记录不展示，新增时清理。

## 服务接口

| 接口 | 用途 | 访问条件 |
| --- | --- | --- |
| `GET /`、`GET /assets/standalone.js` | 公开页面资源，不含个人数据 | 本机来源检查 |
| `GET /session` | 检查访问状态并获取当前运行周期的 CSRF | 会话；否则返回 401 与升级提示 |
| `POST /auth/pair` | 配对码兑换独立会话 | 同源 JSON；每分钟最多 10 次失败尝试 |
| `POST /auth/code` | 生成新码、替换旧的未使用码 | 会话、同源 JSON、CSRF |
| `GET /auth/sessions` | 脱敏列表及当前配对码状态 | 会话 |
| `POST /auth/revoke` | 确认后撤销指定会话 | 会话、同源 JSON、CSRF、显式确认字段 |
| `POST /auth/control` | 仅供本机命令行重新取码 | 本机管理令牌；拒绝带浏览器 Origin / Fetch Metadata 的请求 |
| 业务接口 | 既有账号、同步、备份功能 | 会话；写操作额外校验同源 JSON 和 CSRF |

仅绑定 127.0.0.1；保持 Host、Origin、Fetch Metadata、CSP 和请求体限制。Cookie 使用 HttpOnly、SameSite=Strict，随有效访问续期。本机 HTTP 不等同于远程安全服务，不支持公网或多用户权限隔离。静态文件显式白名单，不开放数据目录。

## 失败与恢复闭环

- 配对码不完整：保留输入，提示补全；失效、已使用或错误：提示获取新码；频率限制：显示等待秒数。
- 写入失败：不消费配对码、不返回登录 Cookie，可排查存储后重试。
- 自己撤销：确认后清除 Cookie、返回配对页；撤销其他会话：当前会话保留，对方后续请求返回 401。已完成或正在执行的业务操作不回滚。
- 服务重启：会话保留、配对码轮换。旧 CSRF 返回 403，客户端刷新校验但不自动重放写操作，由用户决定是否重试。
- 授权丢失：卸载业务界面，回配对页；网络中断：显示重连页。初次访问时服务未运行，由浏览器显示连接失败。
- 旧 v1 凭据升级：原子转为 v2 空会话表，旧凭据失效，业务数据不变；旧 URL 片段移除，不尝试兑换。
- 授权文件损坏：拒绝启动，提供恢复命令。停服后明确执行 `auth:reset -- --confirm`，获得目录锁，保留恢复副本、重建空会话表，再重新启动与配对。
- 所有浏览器都丢失授权或达到上限：优先在可用浏览器撤销；若已无可用授权，可显式停服恢复。不能通过匿名网页生成新码或重置授权。

具体操作与数据目录见 [使用指南](USAGE.md#首次授权与换浏览器)。

## 验证边界

自动测试覆盖会话隔离、重启、撤销、过期、限流、并发兑换、写失败、旧版迁移、CLI 取码与恢复、来源和 CSRF，以及前端不重放写操作。浏览器实测和交付状态单独记录在 `docs/validation`。不把 HTTP 模拟客户端当作 Chrome 或 Edge 原生浏览器验收，也不把独立页面当作 DSH 宿主验收。
