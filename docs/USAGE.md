# 使用与维护指南

[返回中文 README](../README.md) · [English README](../README.en.md)

本页保留首次上手之后需要的运行参数、数据口径、升级与 DSH 安装细节。浏览器配对步骤见[连接器指南](../extension/README.md)。

## 运行参数

在项目根目录使用 `npm start`，启动会先构建界面和连接器。默认监听 `127.0.0.1:43120`；不要通过反向代理暴露到公网。首次打开终端提供的完整授权链接，此后同一浏览器可直接访问本机地址。

更换端口或使用专用数据目录：

```sh
npm start -- --port 43121
npm start -- --root /你选择的独立数据目录
```

独立版与 DSH 版不自动共享数据或授权。不要将独立版 `--root` 指向 DSH 数据目录。升级源码后重新安装依赖并启动；启动失败不会清空账号数据。

### 首次授权与换浏览器

启动时的完整链接包含 `/#` 后的一次性授权码，用于让浏览器取得本机工作台的登录凭据，避免仅凭本机地址就能读取账号数据。**授权码只能成功使用一次，工作台本身可以反复访问。** 每次重启服务都会生成新码，旧链接中的授权码随之失效。

1. 直接复制终端提供的完整链接到目标浏览器地址栏。若链接由聊天提供，也应直接复制；不要先点击到应用内浏览器，再转到 Chrome。
2. 授权成功后，登录状态通过 Cookie 保存在该浏览器中。应用内浏览器、Chrome、不同浏览器配置文件和无痕窗口之间不共享登录状态。页面会自动移除地址中的授权码，不能把此时地址栏的普通地址作为另一个浏览器的首次授权链接。
3. 之后在同一浏览器打开 `http://127.0.0.1:43120/` 即可。正常刷新、关闭页面后重开，以及使用同一数据目录重启服务，都不需要重新授权，前提是浏览器仍保留有效登录 Cookie。
4. 换浏览器、清除站点 Cookie 或登录状态过期后，需要重新授权。若当前启动链接已使用，先停止独立服务，再使用原命令及原数据目录启动，直接将新完整链接复制到目标浏览器。不要删除账号数据或登录文件。

若出现“请使用终端中当前显示的本机链接”，检查是否用了旧链接、缺少授权码，或先在其他浏览器使用了该码。若浏览器提示无法连接本机地址，应先检查独立服务是否仍在运行；重新授权不能解决服务已经退出的问题。使用终端前台启动时需保持进程运行，按 `Ctrl+C` 会停止服务。

这里的工作台登录授权，与浏览器连接器的两分钟配对码是两套不同流程。

## 数据目录与备份

独立版的默认目录：

| 系统 | 目录 |
| --- | --- |
| macOS | `~/Library/Application Support/cross-platform-account-dashboard/standalone` |
| Linux | `$XDG_DATA_HOME/cross-platform-account-dashboard/standalone`；未设置时为 `~/.local/share/cross-platform-account-dashboard/standalone` |
| Windows | `%LOCALAPPDATA%/cross-platform-account-dashboard/standalone` |

DSH 版使用插件配置的本机数据目录。主要文件：

- `accounts.json`：账号、每日记录、计划及恢复状态。
- `browser-connection.json`：本机浏览器授权，权限 `0600`。
- `standalone-session.json`：独立版本机会话，权限 `0600`。
- `accounts.v1.backup.json`：首次从旧数据格式迁移前的逐字节备份。

这些文件包含个人数据或本机授权，不要分享。备份或删除前先停止对应服务；卸载不会删除用户资料。异常断电后若提示目录占用，先确认旧实例已停止，再删除错误提示中指定的遗留 `.standalone.lock`；运行中不能删除它。

### 在设置中查看位置与备份

进入「设置 → 数据与存储」，可查看当前实例实际使用的目录、复制路径，并点击「下载数据备份」。DSH 版显示的是宿主运行本工作台所使用的目录，独立版显示的是当前启动配置的目录；两者不自动共享数据。

备份为带时间戳的 `personal-social-backup-….json` 文件，包含已保存的账号、每日与历史记录、作品库、历史档案和同步设置。导出取已完成保存的一份完整快照；正在同步但尚未保存的数据不在其中。导出不会修改现有账号或暂停同步。页面提示“已发起下载”后，请在浏览器下载列表中确认文件已保存。

备份不包含浏览器配对凭据、工作台登录凭据、浏览器 Cookie、主题偏好或宿主会话，也不下载作品图片与视频。文件含个人数据，请妥善保管。本功能不上传备份到外部服务，也不更改存储目录。

目前没有一键导入入口。需要恢复时：

1. 先停止独立服务，或完整退出 DSH Desktop，避免恢复期间仍有同步写入。
2. 打开设置中显示的原数据目录，将当前 `accounts.json` 另存一份，保留回退副本。
3. 将下载的 JSON 备份复制到该目录并命名为 `accounts.json`，保留其他文件不变。恢复会替换当前业务数据，不会合并备份之后新增的记录。不要用来源不明的文件覆盖数据。
4. 重新启动，核对账号、历史记录和同步设置；备份中的自动同步计划也会恢复。若浏览器连接凭据已丢失，需要重新配对。若恢复失败，停止服务后还原步骤 2 的副本。

## 每日记录与自动同步

每个平台可独立选择每日指定时间，或每 1 / 3 / 6 / 12 小时同步，支持时区设置，默认关闭。

- 每个自然日保留最后一次成功观测。缺测不补零，折线不跨缺口；只有相邻自然日且时区一致才计算净变化。
- 万 / 亿 / k 等约数保留标记，相关净变化标注估算。未知指标不显示为零。
- 修改时区保留原记录的时区，不重写历史日期。旧版最近 90 次快照迁入每日记录，首次迁移前备份原文件。
- 本机服务或 DSH Desktop 与浏览器需保持运行。休眠或关闭期间不采集；恢复后合并执行一次到期任务，不补造历史。
- 各平台任务串行执行。网络失败短暂重试；登录、验证、解析或身份问题暂停受影响平台，处理后回看板继续。失败保留最后成功数据。
- 扩展自动任务使用不激活的专用标签，成功后关闭；可选本机适配器执行计划时可能打开任务窗口，设置中会提示。
- 隐藏平台只影响展示，计划继续运行。解绑会停止计划并保留本地归档；重新绑定同一账号可恢复。修改计划或解绑后，旧任务结果不会覆盖新状态。

## 同步结果与数量说明

总览刷新、详情“同步账号”与定时同步默认执行日常同步：读取账号指标及当前已加载的作品，成功保存即显示“同步完成”，不再滚动寻找历史末尾。它不代表全部历史已收录；页面未加载或解析失败、登录失效、保存失败仍明确报错。

“补齐历史”与“增量同步”是详情里的独立操作。“已更新 · 历史待确认”表示账号指标及已读取作品已经保存，但页面未提供明确末尾或作品列表尚未就绪。可查看账号详情里的原因，稍后继续读取。用户主动暂停、需要登录、验证与连接失败仍分别提示，不会为了显示成功而把未知范围当作全量。

小红书主页可能不提供笔记总数。总数未知且已有本地作品时，总览和详情显示“已收录笔记/作品”，代表本地累计收录量；它可能包含已删除的旧作品，不等于平台当前总数，也不用于平台总数的历史趋势。明确读取到的 0 仍显示 0。

抖音只使用当前选中作品标签的精确数量判断列表读取完成；X 主页帖子总数可能包含回复与转帖，不能用于证明已排除这些内容的采集列表完整。本次更新涉及采集器，使用浏览器扩展时需要下载新版连接器并重新加载；仅更新工作台不会更新浏览器里已经加载的扩展。

## 各平台读取范围

通过官方网页正常翻页或滚动，读取当前登录账号能够访问的作品记录；不调用平台私有接口，也不下载视频、音频文件。

- **累计作品库。** 取消 200 条总量上限；按作品 ID 去重，同一作品更新标题、封面地址等元数据。后续没读到的旧作品不会删除，库中也可能保留已删除或变为私密的作品记录。
- **日常同步与历史分开。** 新旧账号默认只读取当前已加载内容；B 站分别读取视频、图文、音频分类的当前页，不翻页。需要较早作品时使用「补齐历史／继续补齐」；也可主动选择「增量同步」或「重新扫描」。增量会在连续两个不同、非置顶的已知内容窗口后停止，不代表重新核查了全部旧作品；平台重排内容时可用重新扫描补查。
- **分批落盘，暂停可续。** 每批最多 100 条，单轮遍历预算约 90 秒（打开主页、登录检查另计）。这些是处理批次／时间预算，不是作品库容量限制。达到预算会保存检查点，点击「继续补齐」接着读取；日常同步与定时任务不消耗或覆盖历史断点；主动暂停也会暂停该平台自动计划，手动继续成功后恢复。中断后的已确认批次保留。
- **诚实标记范围。** 只有明确末尾、可核验的最后一页或可比的精确分类总量才能确认读完。网页停滞、总量未知或验证码不会被当成结束。检查点恢复会重新打开账号并重放翻页／滚动；平台内容变化可能导致重复扫描，由作品 ID 去重。
- **分类独立。** B 站的视频、图文、音频分别扫描，不再挤占同一个保存名额。平台总数与本地累计记录数是不同口径；每日账号指标独立保存。
- **升级连接器。** 0.6.0 工作台需配合新版扩展才能分批遍历。旧扩展仍可更新账号及当前页作品，但会提示更新连接器，不会宣称已补齐历史。旧版已保存作品直接成为新作品库的起点；升级前建议备份数据，勿用旧版覆盖新版数据文件。

| 平台 | 统计与内容边界 |
| --- | --- |
| 小红书 | 作品总量未知时保持未知 |
| 抖音 | 读取本人作品，不混入喜欢或收藏 |
| 哔哩哔哩 | 读取本人投稿页的视频、图文与音频；分别展示平台总数、已读取数量与未读取状态，不混入收藏或推荐，不保证全部历史投稿 |
| X | 只保存本人已加载帖子，排除他人转帖与推荐；主页帖子总数可能包含回复和转帖，不等于列表长度；无可靠累计获赞值，因此保持未知 |

各平台页面结构变化可能导致读取失败。连接器的「已提交」仅表示原始结果已送达；看板完成身份核验和落盘后才算同步成功。

## 连接器、授权与升级

“自动选择”优先使用已配对的浏览器扩展；未配对时尝试 Ego Lite。已配对的扩展离线时不会自动切换到另一个浏览器。也可明确选择“浏览器扩展”或“Ego Lite 专用连接”。主流程不要求改变系统默认浏览器，单纯打开浏览器不能代替授权。

Chrome 最低 120，Edge 建议当前稳定版；Firefox 115+ 使用临时附加组件，重启后需重新加载。Ego Lite 为可选适配器，默认命令位置 `~/.local/bin/ego-browser`，DSH 插件可用 `browserExecutable` 配置；独立版可传 `--browser-executable`。

- 连接器约每 30 秒检查待办，休眠时可能更久；可以从扩展主动检查任务。
- 一次仅授权一个扩展连接；重新配对替换旧凭据，不复制不同浏览器的登录状态。连接码 2 分钟过期且仅一次有效。
- 工作台升级不会替换浏览器里已加载的扩展。下载新连接器，替换原加载目录文件，在扩展管理页重新加载；保留原目录与扩展身份可保留授权。Firefox 重新载入新包。
- 扩展只申请 `storage`、`scripting`、`alarms`、本机地址及平台必要域名权限；不申请 Cookie、历史、调试或全站访问权限。本机桥接校验 Host、扩展 Origin 与随机凭据。DSH 接口受宿主认证保护，独立版使用本地会话、同源与请求校验。

详细恢复步骤及权限说明见[连接器指南](../extension/README.md)和[安全说明](../SECURITY.md)。

## 长页面与操作提示

设置和账号详情的顶栏左侧始终提供“返回账号总览”，返回时保留总览原来的滚动位置。向下滚动约一屏后，右下角出现圆形“回到顶部”按钮，悬停或键盘聚焦可查看标签。

手动操作结果在工作台可视区域顶部浮动显示，不随正文滚走，约 4 秒后收起；鼠标悬停或键盘聚焦时暂停计时。同步失败原因和重试入口仍保留在对应账号处，字段校验仍显示在表单旁。自动同步成功不会反复弹出通知。同步成功不代表历史作品已全部读取，完整性以账号详情中的状态为准。

## 意见反馈

设置底部、历史档案之后的“帮助与反馈”可打开[飞书反馈表单](https://my.feishu.cn/share/base/shrcn3QhjgppqaD3vnhVP4KUWXf)，在新标签页填写。仅反馈类型和描述必填，截图、联系方式和诊断信息选填；选择“使用问题”时可补充操作步骤与期望结果。联系方式仅用于回复本次反馈。

点击“查看诊断信息”先展示预览，再选择复制。内容只包含工作台版本、运行方式、连接选择及连接状态，不含账号资料、主页地址、连接码、授权凭据或原始错误。工作台不会自动上传这些信息，是否粘贴到飞书表单由你决定；提交成功由飞书页面确认。

维护反馈入口时修改 `src/client.js` 中的 `FEEDBACK_URL`，然后重新构建。飞书 CLI 仅用于维护表单，用户运行工作台无需安装 CLI，也无需配置飞书应用密钥。

## 安装到 DSH Desktop

这里的宿主指 [DSH Desktop 官方桌面应用](https://dshdesktop.com/)，不泛指其他 DeepSeek Harness 环境。2026-10-17 读取的本机应用版本为 **0.12.0**，本地 CLI 已确认接受 tgz；这不代表本轮原生界面验收通过。开发者请遵循 [本地开发、更新与验收流程](DSH-LOCAL-DEVELOPMENT.md)，每次核对当前安装能力。

先按[贡献指南](../CONTRIBUTING.md)准备 Node.js 22+ 和 pnpm 10.34.5，在项目根目录构建并打包：

```sh
pnpm install --frozen-lockfile
pnpm test
pnpm build
pnpm check
pnpm pack
```

产物包含构建后的客户端、服务端、两套本地连接器和说明，无运行期远端脚本。使用当前 Desktop 明确支持的本地包安装入口；不要将构建成功或配置存在当成已在宿主加载。

<details>
<summary>macOS 上已使用的 DSH CLI 安装方式</summary>

以下路径对应本机 DSH Desktop 布局；其他安装位置请先确认 CLI 路径与本地包支持。请使用当前 `pnpm pack` 输出的包文件名；下方会从 `package.json` 读取版本。

```sh
PACKAGE_VERSION="$(node -p 'JSON.parse(require("fs").readFileSync("package.json", "utf8")).version')"
PATH="$HOME/Library/Application Support/dsh-desktop/harness/.desktop-bin:$PATH" \
DSH_HOME="$HOME/Library/Application Support/dsh-desktop/harness" \
"$HOME/Library/Application Support/dsh-desktop/harness/.desktop-bin/node" \
'/Applications/DSH Desktop.app/Contents/Resources/app.asar/node_modules/@deepseek-ai/dsh/lib/bin.js' \
plugin --profile web add "$PWD/dsh-workbench-personal-social-local-${PACKAGE_VERSION}.tgz" \
--offline --ignore-scripts --config.auto-install-peers=false
```

`--offline` 依赖本机已有缓存；缺少缓存时不能认为安装通过，应先查明缺失依赖再处理。

</details>

安装后按宿主提示重启，从工作台市场「已安装」确认条目及运行状态，再展开左侧栏，通过「工作台」右侧的当前名称／切换区域选择看板；新本地工作台加载后自动加入切换菜单，没有单独的「添加」按钮。若 Agent 正运行在这台 DSH Desktop 内，由用户完整退出并重新打开后继续验收。历史原生验收记录不代表本轮加载结果；独立版与浏览器预览也不能代替宿主验收。

## 开发与发布身份

「添加平台 → 自定义平台」会收集官方域名、主页、指标和登录要求，生成针对项目的开发提示词。它不会执行任意脚本或直接启用新平台；实现与测试方法见[平台开发指南](PLATFORM-DEVELOPMENT.md)。
