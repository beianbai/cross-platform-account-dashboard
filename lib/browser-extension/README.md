# 跨平台账号看板 · 本地浏览器连接器

这是用户自行加载、只在本机使用的扩展，源码随项目公开，尚未提交浏览器商店。工作台通过扩展连接已授权的浏览器。

## 支持范围

- Chrome / Edge 等支持 Manifest V3、scripting 和半分钟 alarms 的现代 Chromium 浏览器：加载 chromium 目录。Chrome 最低 120；Edge 建议使用当前稳定版。其他 Chromium 浏览器须确认允许本地扩展，不能仅因内核相同就保证支持。
- Firefox 115+：加载 firefox 目录的 manifest.json 作为临时附加组件。**未签名，本地临时安装在重启 Firefox 后失效，需要重新加载。** 不声称已完成正式长期分发。
- Safari 17+（macOS）：新增本地试用适配资源，复用同一采集逻辑；需要完整 Xcode 构建包含扩展的 Mac 应用，或在提供临时加载入口的新版 Safari 中测试。17.0 是本轮目标下限，不代表逐版实机认证；使用者已验证本机启用、配对及哔哩哔哩登录后同步；其他平台完整采集、后台同步与恢复仍待实测，暂无正式签名安装版。
- 移动浏览器以及禁止开发者扩展的受管浏览器：当前没有可用适配器。不要求改系统默认浏览器；现有缓存仍可浏览。

## Chrome / Edge 首次连接

1. 解压整个连接器包，保留文件夹，不要只移动 manifest.json。
2. 在你自己常用的浏览器打开扩展管理页面：Chrome 为 chrome://extensions，Edge 为 edge://extensions。
3. 自行打开“开发者模式”，点“加载已解压的扩展”，选择 chromium 文件夹。仔细确认扩展权限后安装。
4. 回 DSH Desktop 或独立版的“跨平台账号看板”，打开“连接浏览器”，点“生成连接码”。
5. 打开该浏览器工具栏中的“跨平台账号看板 · 浏览器连接”扩展，粘贴连接码，填写便于识别的名称，点“授权连接本机看板”。连接码仅 2 分钟有效、只能使用一次；不要分享。
6. 回工作台选择平台并开始读取。扩展在这个浏览器中新开专用平台标签。如果未登录，亲自在平台完成登录/验证码，再回工作台点“继续读取”。已有登录态直接复用，账号密码不经过工作台。

## Firefox 临时连接

在 about:debugging#/runtime/this-firefox 选择“临时载入附加组件”，选择 firefox/manifest.json，再按上面的 4–6 步操作。扩展在浏览器重启后需要重新加载并按需连接。这是本地开发安装，不是签名商店版。

## Safari 本地试用（macOS）

这是供本机开发验证的适配包，**不是双击即可安装的签名版，已由使用者验证本机启用、配对与哔哩哔哩同步，完整验收仍在继续**。Chrome / Firefox 的目录不能直接按原有方式安装到 Safari。浏览器登录态不会跨浏览器复制；需要在 Safari 自己登录平台。

### 先明确：你需要做什么，开发者继续做什么

最终用户只需安装开发者提供的正式 Safari 连接器，不需要 Xcode。当前参与本机开发联调的使用者已从 App Store 安装完整 Xcode；该步骤只服务于本次开发验证，不应成为产品安装要求。开发者负责检查工具链、生成工程、构建 Safari 应用、修复兼容问题、重新打包，并记录验收结果。Safari 的安全选项、扩展启用、网站权限，以及平台登录或验证码由使用者本人操作；原生界面工具不可用时，开发者提供具体点击步骤与预期结果，协同完成界面验收。

**安装 Xcode 只是前置条件，不等于 Safari 插件已经交付。** 完整流程是：

`安装 Xcode → 首次初始化 → 检查工具链 → 生成并构建 .app → Safari 启用与网站授权 → 配对 → 手动同步 → 自动同步与重启恢复 → 更新验证 → 记录真实结果`

### 1. 下载并安装完整 Xcode（开发环境准备）

1. 在苹果菜单「关于本机」确认 macOS 版本。本轮最新工具探测为 macOS **27.2**、Safari **27.2**、Xcode **27.2**；历史环境数据不代表当前状态。App Store 版本仍需与目标系统兼容。
2. 打开 [Apple Xcode 资源页](https://developer.apple.com/xcode/resources/)，进入 **Additional tools / View downloads**，或直接打开 [Apple 官方更多下载](https://developer.apple.com/download/all/?q=Xcode)。使用自己的 Apple Account 登录；Apple 说明旧版 Xcode 下载不要求付费 Apple Developer Program 会员。
3. 在下载列表查找与当前 macOS 兼容的完整 **Xcode**，不要选 **Command Line Tools for Xcode**。旧系统下载前对照页面的系统要求和 [Apple Xcode 兼容列表](https://developer.apple.com/support/xcode/) 确认版本。若选择其他版本，同样核对系统要求；不为了这一项默认升级 macOS。
4. 下载对应的 `.xip`，在 Finder 双击解压，把生成的 `Xcode.app` 拖到「应用程序」。下载文件与展开后的应用会同时占用空间，请按下载页标示的大小预留额外解压空间。
5. 从「应用程序」首次打开 Xcode。由本人阅读并接受许可；如要求安装必需组件或输入 Mac 管理员密码，由本人完成。等待初始化结束，能看到 Xcode 欢迎页后再继续。不需要为本轮未签名的 macOS 测试构建购买会员，也不需要先注册付费证书或创建项目；可选 iOS/其他平台运行时不是本轮必需。
6. 与开发者协作时，完成到这里后告知 **“Xcode 已安装并首次打开完成”**，由开发者继续检查和构建，不需要自己从头走完开发流程。

最新版 Xcode 可通过 [Mac App Store](https://apps.apple.com/app/xcode/id497799835) 安装，但仅在其系统要求与当前 Mac 匹配时使用。若 Xcode 不能打开、组件安装失败或提示系统版本过低，保留具体错误并交给开发者定位，不反复尝试未知版本、不绕过系统安全提示。

### 2. 检查工具链并构建（开发者负责；自行使用者也可执行）

准备 Node.js 22+ 和已经完成首次初始化的完整 Xcode。以下设置只对当前终端有效，不全局切换系统开发工具：

```sh
export DEVELOPER_DIR="/Applications/Xcode.app/Contents/Developer"
xcodebuild -version
xcrun --find safari-web-extension-converter
```

旧版工具名是 `safari-web-extension-converter`；新版改名为 `safari-web-extension-packager`，如旧名未找到再检查：

```sh
xcrun --find safari-web-extension-packager
```

预期：`xcodebuild -version` 显示所装 Xcode 的版本；两个 Safari 工具名中至少一个能返回真实路径。若只看到 `/Library/Developer/CommandLineTools` 或两个工具都不存在，工具链未就绪，应检查 Xcode 路径与首次组件安装，不进入“已构建”状态。

下载连接器 ZIP 并完整解压后，在**含 `build-safari.mjs` 与 `safari` 文件夹的解压目录**执行：

```sh
node build-safari.mjs --output ./safari-local-build
```

从本项目源码开发时，在项目根目录执行：

```sh
pnpm run build:safari
```

脚本生成自包含的 macOS Xcode 项目，再构建带 ad-hoc 本地签名的 Debug 应用（无开发者证书、未公证，Safari 按未签名开发扩展处理）；源码入口默认输出 `.install/safari-local-build`。脚本兼容旧版 `project.pbxproj` 与新版 `project.xcproj` 设置文件，修正打包工具可能遗留的应用标识，并对应用及内嵌扩展执行签名完整性检查。成功后终端会打印 `.xcodeproj` 和 `.app` 的**实际绝对路径**。可用 `--project-only` 只生成工程；输出目录必须不存在，重做时通过 `--output` 选择新目录，不覆盖旧工程。

脚本不下载 Xcode、不修改 Safari 安全设置、不安装应用，也不发布到商店。若编译失败，由开发者读取实际错误、修复后重试；工程生成成功但 `.app` 没有构建完成，仍不算可用插件。

### 3. 在 Safari 中启用（使用者本人操作）

拿到开发者已经构建好的本地测试 `.app` 时，直接从这里开始，不需要安装额外工具或重复构建。ad-hoc 签名只保证本地文件完整性，没有正式开发者身份；启用它会临时允许 Safari 运行未签名开发扩展。此选项仅用于联调，不属于普通用户的最终安装流程。

1. 在 Finder 打开构建成功的 `Account Dashboard Safari.app`。打开应用只使扩展可供 Safari 识别，不代表已经启用。
2. Safari 17 中打开「Safari → 设置 → 高级」，勾选「显示网页开发者功能」（英文 **Show features for web developers**）。
3. 在「设置 → 开发者」勾选「允许未签名的扩展」（**Allow unsigned extensions**）。它允许本机开发扩展运行，需要使用者了解用途并自行开启；Safari 退出后会重置，重开需要再次开启。本轮不会由脚本替你更改此设置。
4. 在「设置 → 扩展」找到「跨平台账号看板 · 浏览器连接」并勾选启用。找不到时先确认 `.app` 已实际打开、未签名选项已开启，仍失败由开发者排查工程与加载记录。
5. 按需允许扩展访问本机 `127.0.0.1` 与要同步的平台网站；Safari 可能在首次访问时再询问。若有多个 Safari 浏览场景（Profiles），在实际登录平台的场景中启用扩展。
6. 在 Safari 工具栏找到连接器按钮。能打开弹窗，且显示“尚未连接”或连接输入框，才算完成启用；仅在设置中看到名称还不足以证明运行正常。

### 4. 配对并完成首次手动同步（双方协同）

1. 保持 DSH Desktop / 本机服务与 Safari 运行，在看板「浏览器连接」生成新连接码。一次只授权一个采集浏览器：**Safari 配对成功会替换 Chrome / Firefox 的旧授权**；已有账号、作品和历史保留。
2. 在 Safari 连接器里粘贴连接码，填写便于识别的浏览器名称，再授权。预期：连接器确认连接成功；看板显示本次配对成功与“已连接”。不要把连接码发给别人，也不要仅凭本机服务的模拟测试认定此步骤成功。
3. 在 Safari 自己登录需要验证的平台。账号密码和验证码由本人操作；Chrome 的登录态不会自动转移。
4. 使用者明确选择要验证的平台并主动开始一次同步。若提示登录或验证，在 Safari 处理后回看板点“继续读取”。开发者默认使用隔离测试数据；不为验收擅自采集真实账号或解除已有绑定。
5. 预期：看板确认保存成功，账号、指标、作品与页面相符；“已提交”只表示连接器交回结果，不能代替看板保存成功。失败时保留旧数据，由开发者排查权限、本机通信、页面识别或兼容问题。
6. 小红书、抖音、哔哩哔哩和 X 分别记录结果。没有可用账号或未获授权测试的平台标记待验证，不能从一个平台成功推断四个平台都通过。

### 5. 自动同步、重启与更新验收（开发者主导，必要时由使用者操作界面）

- **自动同步**：经使用者同意，为测试平台临时开启计划，记录到期前后的同步时间和保存结果；结束后恢复原计划。不以手动点击“检查待执行任务”代替后台到期触发测试。
- **Safari 重启**：先结束当前任务，由使用者正常退出并重开 Safari；未签名测试选项按 Apple 规则重新开启。检查扩展启用状态、授权和再次同步是否正常，需要重新配对时记录实际原因，不默认清空数据。
- **休眠恢复**：休眠期间不承诺采集；唤醒后验证能恢复后续任务，失败时明确报告，不伪造离线历史。
- **更新**：使用相同应用身份构建下一份资源并更新，检查原授权和已有数据。不得用卸载、删授权或清空看板数据掩盖更新失败。
- **结论**：分别记录工程生成、应用构建、Safari 加载、配对、各平台读取、保存、计划触发、恢复和更新。存在失败或未验证项时保留真实边界；使用者已授权将已验收的本地接入与后续缺陷修复分别提交；未授权合并、推送或公开分发。

### 新版 Safari 的临时加载入口

Apple 当前文档也提供「设置 → 开发者 → Add Temporary Extension…」。**仅在你的 Safari 确实有此入口时**，可选下载包内的 `safari` 文件夹临时测试，无需生成 Xcode 项目。临时扩展在退出 Safari 或 24 小时后移除，不适合长期运行自动同步；旧版本不能假设有此入口。

### 更新与正式分发边界

保留原应用、工程和扩展身份，不要通过卸载来更新或清空授权。用新资源构建同一身份的应用，替换旧应用后在 Safari 检查扩展；若来源标识变化导致配对失效，再生成新连接码，账号历史不受影响。未签名测试不等于正式分发；正式安装版需要开发者签名，可走 App Store，或 Developer ID 签名、公证后分发。本轮不创建开发者账号、不申请证书或上传代码。

官方说明：[运行与测试](https://developer.apple.com/documentation/safariservices/running-your-safari-web-extension)、[打包工具与参数](https://developer.apple.com/documentation/safariservices/packaging-a-web-extension-for-safari)、[分发方式](https://developer.apple.com/documentation/safariservices/distributing-your-safari-web-extension)。

## 日常使用与恢复

- 一次只授权一个浏览器。重新配对成功后会使旧浏览器凭据失效，不混用不同浏览器账号；切换真实平台账号仍需先解除旧本地账号绑定。
- 连接器保留本机授权，不存平台密码或 Cookie。Desktop 重启通常沿用原端口和授权；如果本机端口被其他程序占用而发生变化，需要重新生成连接码。
- 扩展约每 30 秒轮询本机待办，执行手动同步及用户已开启的平台计划。工作台发出同步到扩展接收通常需要 0–30 秒；浏览器休眠可能更久。也可点扩展里的“检查待执行任务”。
- 完成登录后必须在工作台点“继续读取”；本版不在用户登录过程中持续监视密码框或抢先点击平台。
- 自动任务创建不激活的专用标签，成功后关闭；需要登录或验证时保留页面，等待用户继续。网络重试只复用尚未被用户激活或导航的专用标签。
- 扩展断开按钮停止该扩展轮询并清除本地凭据；工作台的“撤销浏览器授权”使连接 token 在服务端失效。同步期间先等待当前任务结束（最长约 3 分钟），再撤销。
- 如出现连接错误，检查 Desktop 或独立服务是否运行，扩展是否启用，然后重新配对。不要将连接码提交给任何网站。

## 权限与安全边界

扩展仅申请 storage、scripting、alarms，以及 127.0.0.1 和四个平台所需的精确站点权限；不申请 cookies、history、debugger、webRequest 或全站访问权限。不扫描既有标签，不读取其他浏览器配置/密码库，不复制登录态，不执行平台互动。

本机服务只监听 127.0.0.1，校验 Host/Origin，并要求随机授权凭据；网页本身不能调用。DSH 主界面接口由宿主认证保护，独立版由本机会话和同源校验保护。授权配置只保存在插件内部 browser-connection.json（0600）；账号数据仍在原 accounts.json，不包含授权密码。不要分享这些本机内部文件。

扩展将当前页昵称、头像、指标和当前已加载作品发送到本机，服务端重新验证平台地址及账号身份后才保存。无法读取不等于零；失败不会覆盖旧数据。所有连接代码包含在本地扩展中，不从服务器接收任意脚本、不下载或执行远程代码。

需要更新连接器才能应用修复：Chromium / Firefox 覆盖原扩展目录后重新加载；Safari 用同一身份的新版应用替换原应用，正常重开后检查版本为 0.8.1。保留原授权和历史，不通过卸载更新；若 Safari 尚未载入新资源，先退出 Safari，再重开连接器与 Safari。Xcode 只供开发者构建，使用者无需重复构建。
